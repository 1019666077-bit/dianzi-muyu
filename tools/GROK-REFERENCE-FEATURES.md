## Grok 交付物（必须产出）

### 1. 《功能差距矩阵》Markdown

行：参考功能；列：**已有 / 部分 / 缺失**；加 **建议优先级 P0–P2** 与 **是否适合 v1.0 上线**。

### 2. 《实施方案》（按模块）

每个模块包含：

- **产品行为**（与参考一致或刻意差异的理由）
- **数据结构**（扩展 `storage` JSON 字段，含日期 rollover 逻辑伪代码）
- **页面/route**（是否新增 `pages/stats/stats`）
- **UI 方案**（右侧 icon 栏 vs 保留三 Tab 的融合建议——**须保留念珠/颂钵作为差异化**）
- **与 P0 合规**：重置是否确认弹窗、自动敲是否仍走 `utils/ad.js`
- **包体/性能**：不引入 Three.js；2D/现有 premium 分层即可

### 3. 《分期路线图》

- **v1.1 最小对标**：数据页 + 本次/今日/总 + 日切；重置（确认）；自动 toggle（可保留广告门槛或免费 toggle——二选一写推荐）
- **v1.2 体验**：主界面右侧快捷栏、浮字 +1 样式、可选木鱼专注模式（隐藏 Tab）
- **不做**：盲目抄佛像背景（版权/审核）；除非用户明确要类似氛围图

### 4. 《质量检查清单》

## 设计原则（写入方案）

1. **差异化保留**：三模式 + 精修皮肤是我们优势，参考品只有木鱼，**不要删 Tab 换纯抄**。
2. **统计口径**：三种模式敲击是否 **共用功德池**（当前是共用 `total`）——方案中明确并建议是否在数据页分模式展示。
3. **重置范围**：重置「本次」vs「总功德」vs「全部数据」——需产品定义，默认 **仅重置本次** 或 **总功德需二次确认**。
4. **自动敲**：参考为 toggle；我们现为限时奖励——方案给出 **融合**（例如：免费 slow auto vs 看视频 fast auto）。
